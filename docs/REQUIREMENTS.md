# 满箱 · 需求

## 定位

**个人自用工具**，不是产品。目标是自己记一笔加油只要几秒，不被弹窗、推荐和会员打断。

不是要跟谁竞争，也不是要做给第二个人用。所有取舍围绕一句话：
**在加油站排队时，记一笔加油不超过 2 个数字、3 次点击。**

## 硬约束

| 约束 | 内容 | 原因 |
|---|---|---|
| C-1 | **`INTERNET` 只用于三个白名单域名** | 网络请求收口到单例 OkHttp + `network_security_config` 白名单。权限开着，但出口被钉死在油价、气象、地图三家 |
| C-2 | **多车，但车辆之间完全隔离** | 每条记录必须挂在一辆车上；统计、趋势、加油站、默认值都只在当前车内成立，绝不跨车混算 |
| C-3 | 只记加油，不记保养/保险/罚款 | 范围外，砍掉 |
| C-4 | 不做 OBD / 蓝牙 / 车机对接 | 数据源只有满箱法一条 |
| C-5 | 无后端、无账号、无云同步 | 联网只做**单向读取**，不上传任何用户数据 |
| C-6 | 零第三方 SDK | 不引入任何分析、崩溃、推送、广告库 |

### C-1 展开：联网不是通行证

`INTERNET` 在 Android 里是普通权限，Manifest 一行、安装时静默授予，**不弹窗** —— 这是它和定位权限的根本区别（后者是危险权限，必须弹窗）。所以联网本身不打断录入流程。

但权限一旦声明，所有 SDK 都能用。所以把出口钉死，而不是靠自觉：

```
network_security_config.xml
  cleartextTrafficPermitted = false          // 禁明文，杜绝降级注入
  domain-config: 油价源 / 气象源 / 地图源     // 只有这三个 host 能通
```

再加代码层约束：**全 App 只有一个 OkHttp 实例**，由拦截器强制校验 host。判据 E4~E6 可程序化验收。

**不做上传。** 联网只读取油价、气温、POI，本地记录一条都不出设备。这样即便权限开着，也不存在数据外流的路径。

## 功能需求

### R1 记录一次加油

必填：**里程（odometer）**、**金额（amount）**。
选填 / 自动推导：升数、单价、加油站、备注。
归属：**始终记在当前车上**（录入页顶部显示「记到 车名 · 车牌」，可切换）。

- 里程与金额是唯一必须手输的两个数字。
- 升数与单价：填任意一个，另一个由 `金额 / 单价` 或 `金额 / 升数` 反推。
- 单价默认值 = **当前车**上次记录的单价（不是指导价 —— 你常去的那家站才是准的）。
- 加油站默认值 = **当前车**上次记录的加油站。
- 标号默认值 = 该车的 `fuelGrade`；在油价面板里改标号即改这辆车的默认。
- 键盘为数字键盘，进入页面即聚焦里程字段。

#### 只填金额时的推算标记

**允许只填金额就保存**，升数按默认单价反推。但这类记录必须标记 `estimated = true`，历史里在升数后显示「估」。

判定规则：用户手动改过单价或升数 → `estimated = false`；两者都没动 → `true`（单价是默认值，未必等于当站实际挂牌价）。

理由：默认价与实际价差 0.2 元时，44 L 会算出 1 L 的油量偏差，摊到 585 km 上就是 0.19 L/100km。这是**系统性偏移**，不随机跳动，不影响趋势判断，但必须可追溯 —— 否则半年后分不清哪些点可信。

### R2 加满标记

每条记录带 `is_full` 布尔值，默认 `true`（因为平时基本都加满）。

它不是可选项 —— 油耗曲线能否成立全靠它。默认值让常见路径零操作，偶尔没加满时才需要点一下。

### R3 首页

打开即可见，不需要任何点击。按信息优先级分四层，**层数固定，顺序不随数据变化**：

**第一层 · 核心（永远展开）**
- 当前油耗：最近一次有效区间，大字
- 与上一箱的差值（降绿 / 升橙）

**第二层 · 事实（永远展开）**
- 上次加油：距今几天 / 油量 / 金额
- 累计四个数：累计行驶、累计油费、累计平均油耗、加油次数

**第三层 · 建议（永远展开）**
- 加油建议：**车标了油箱容积就按「油箱容积 ÷ 当前油耗」算满箱续航**，没标则退回「上次加油量 ÷ 当前油耗」。给出预计加油时的里程，并在卡片小字里写明这个数是怎么估的（哪种来源、用了多少升）

**第四层 · 趋势（默认折叠）**
- 油耗折线 + 气温背景柱，点标题展开。默认折叠是因为它占高度且不需要每天看。
- 展开后附**归因结论**（见 R11）。

底部一条「距上次记录 N 天」的轻提示。

### R4 历史记录

按日期倒序的列表，每条显示：日期、里程、升数（估算的带「估」标）、金额、该次区间油耗。
支持编辑与删除（长按或右滑）。

### R5 趋势

油耗随时间的折线图。只在有有效油耗值的记录上出点。
气温以背景柱形式叠在同一条时间轴上（见 R11），不设第二根 Y 轴。

### R6 车辆与切换

一辆车一条记录：车名、车牌、油箱容量、默认标号。
用途为预填默认值、合理性校验（单次加油量 > 油箱容量 → 提示）、以及作为记账的归属主体。

**切换入口只有两处，都在一步之内：**

| 位置 | 行为 |
|---|---|
| 首页车名（车名右侧 `▾`） | 弹出车辆列表，点一下即切换 |
| 录入页顶部「记到 X ›」 | 同上；在录入中途发现选错车，可直接换 |

车辆列表每行显示：车名、车牌 · 默认标号、该车记录条数。列表底部是添加车辆（名称必填，车牌选填）。

#### 切车必须遵守的三条

1. **所有视图跟着切**：首页油耗与统计、历史列表、趋势与归因、加油站列表、录入默认值，全部只反映当前车。
2. **录入中途切车，清空里程与金额**。里程表是每车一套数，拿 A 车的读数去记 B 车是最容易犯且最难发现的错。切换后重新带出 B 车的上次单价与加油站。
3. **油耗区间按车分组计算**，不能把所有记录按里程一次排序 —— 两辆车的里程表读数完全可能交叠，混排会把区间算串，得出离谱的油耗。

#### 零状态

- 一辆车都没有时：首页显示「添加车辆」，点录入直接弹添加面板，不允许记一条「没有车」的账。
- 有车但没有记录时：首页油耗显示 `—`，提示「这辆车还没有记录」，不显示 0 或 NaN。
- 新车第一条记录：不产生油耗，历史里显示「基准 · 首次记录」。

### R7 数据导出 / 导入

**导出**：全量 CSV —— **含所有车辆**，不只当前车（备份要完整）。UTF-8 带 BOM（Excel 直接打开不乱码）。文件名 `fuel_YYYY-MM-DD.csv`。按日期、里程排序。字段：

```
vehicle,vehicle_name,date,odometer,liters,amount,price,is_full,station,estimated
陕A·8K2L7,我的车,2026-05-08,8200,45.00,368.00,8.17,1,"中石化 · 科技路",0
```

车牌是归车依据，车名一并导出，换机恢复后名字不会退化成车牌号。

**导入**：合并而非替换。按 `vehicle + date + odometer` 判重，重复即跳过。完成后明确告知：导入 N 条、跳过 M 条已存在、K 行无法识别。

- 车牌已存在 → 归到那辆车；车名为空且现存名字等于车牌时，顺手把名字补回来。
- 车牌不存在 → 新建一辆车，名字取 `vehicle_name`，缺失则用车牌。
- 兼容旧格式：无 `vehicle_name`、乃至无 `vehicle` 列的文件都能导入；无车辆列的记录归入**当前车**。

**导入不做录入校验，但结果必须标记异常。** 里程回退，或区间油耗超出物理合理范围（> 25 或 < 1 L/100km）的记录在历史中显示「异常 · 核对里程」，并且**不参与**首页当前油耗、趋势图、归因、累计平均。

> 下限取 1 而不是 3：3 是轿车经验值，摩托车正常油耗 1.8~2.5，用 3 会把整张表判成异常。1 仍能拦住漏记加油导致的天文低值。

理由：录入页有实时校验，导入是唯一绕过校验的入口。宁可标记，不可静默 —— 静默的脏数据会伪装成「当前油耗」出现在首页大字位。

自用 App 没有云同步，换机或重装就是数据全丢。这条**不是锦上添花，是兜底**。

### R8 油价

- 支持 92# / 95# / 98# 三个标号，**默认 92#**，录入页顶部可切换。
- 切换标号后，单价自动带出该标号的价格。
- **油价只用于预填，绝不覆盖用户手填过的单价。** 加油站允许在指导价基础上浮动 5%，民营站常便宜几毛，加油机的数字永远比任何接口准。
- 油价面板必须显示**数据时间**与「以加油机挂牌为准」。

#### 同步策略：惰性、有缓存、失败不吵

国家发改委无公开接口，只发调价通知（每 10 个工作日一次，仅吨价）。可用的是第三方聚合（showapi 138-46、`mxnzp.com/api/oil/search`、即刻数据），数据源为发改委指导价，覆盖 31 省。

| 触发时机 | 行为 |
|---|---|
| 打开录入页 | **只读本地缓存，零请求** |
| 缓存超过 7 天 | 静默刷新一次；失败则继续用旧值 |
| 点面板「刷新」 | 强制请求一次，3s 超时 |
| 请求失败 | 不弹错误、不置空，面板只显示上次成功同步的时间 |

设计理由：油价 10 个工作日才变一次，一个月最多变两三次。**不做后台轮询、不做定时任务、不做 WorkManager**，只在有人打开界面时才可能发一次请求。代价是可能显示几天前的价格 —— 而价格本来就没变。

请求失败绝不阻断录入，这是底线：油价是预填值，不是依赖项。

### R9 加油站

**历史快选为主，定位为辅。**

主路径（零权限）：点击加油站字段弹出列表，只列**自己加过的站**，按加油次数降序，每项右侧显示去过几次。底部「+ 手动输入」用于新增。

辅助路径：字段下方一行「定位」，点了才请求一次位置。定位成功后在字段位置显示最近的站名与距离，用户点「使用」才填入。

- **不后台定位、不存坐标、用完即弃。**
- 只申请 `ACCESS_COARSE_LOCATION`（大致位置）。加油站之间间隔通常以公里计，模糊定位足够区分，而 Android 12+ 上「大致位置」的心理负担远小于「精确位置」。
- **定位被拒或没信号时，历史列表照常可用。** 这是必须存在的降级路径，因为加油站地下层常年没信号。
- 默认值仍取上次记录的加油站，不因为是「最近的」就自动改掉。

> 定位解决的场景是「临时在别处加了油」。常去的那两三家，列表比定位快。

### R11 气温归因

这是联网换来的唯一真正增量，也是这个 App 区别于同类的唯一位置。

同类只给一条折线，不回答「我的车到底正不正常」。气温是唯一能自动获取、且能解释油耗波动的外部变量：

- 每段有效区间按**天数加权**计算该区间平均气温（取区间内每日均温的平均，不是取中点那天）。
- 对「区间油耗 ~ 区间气温」做一元线性回归，得到斜率、相关系数 r、残差。
- 展示三个数：**每 10℃ 的油耗变化**、**最热与最冷区间的实测差**、**最大残差**。
- 给一句结论：
  - 最大残差 < 0.35 L → 「车况正常，那点起伏是空调和冷启动」
  - 否则指出具体是哪一段偏离、偏高多少，提示看行驶工况（拥堵/多载/短途）

**为什么用残差而不是直接看趋势：** 气温只能解释一半左右的波动（实测 r≈0.71，r²≈50%）。剩下那一半才是值得看的东西 —— 但只有先把气温这一半减掉，才看得出剩下一半里有没有真问题。直接看折线，夏季高、秋季低，看起来像回事，其实什么都没说明。

数据来源：气象接口的日均温（和风天气免费档足够）。**失败时不显示归因块，不显示 0 或 NaN。** 缺气温就不做归因，折线照常。

## 非功能需求

| 编号 | 需求 | 判据 |
|---|---|---|
| N1 | 网络出口受限 | `network_security_config` 白名单仅含三个 host；`cleartextTrafficPermitted=false` |
| N2 | 冷启动快 | 点击图标到录入页可交互 ≤ 1.5s（中端机），首页不因等网络而白屏 |
| N3 | 录入足够短 | 常规一次录入 ≤ 2 个数字输入 + ≤ 3 次点击 |
| N4 | 断网可用 | 飞行模式下全部记账功能可用；油价、气温、定位三项各自降级，不影响保存 |
| N5 | 数据不丢 | 杀进程、重启设备后记录完整；导出 CSV 可还原 |
| N6 | 不打扰 | 除「久未记录」的首页提示外，无任何通知、弹窗、红点 |

## 明确不做

社交、排行榜、加油比价、油价行情推送、**保养提醒（含里程推算）**、保养项目记账、账号、云备份、桌面小组件（第一版不做）、OCR 识别小票、后台定位与地理围栏。

多车**不做**的部分：车辆之间的对比图表（「两车谁更费油」）、车辆照片、删除车辆（第一版只做加车与切车；删车涉及记录连带删除，等真有这个需求再设计）、记录在车辆之间迁移。

理由统一：自用场景下这些都不解决「记得快」这一个问题，只是增加代码量和维护面。

**注意「不做加油比价」这一条仍然成立。** 联网拿到的是全省最高零售价，不是某家站的实际价，用它排比价只会误导。
